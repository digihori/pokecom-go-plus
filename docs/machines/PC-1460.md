# PC-1460 — Core / Studio

2026-10-13実装。Machine IDは `pc-1460`。1450の容量違いとして扱わない。

| 項目 | 今回の値（Pokecom GO参照） |
|---|---|
| CPU | 768 kHz / 3 = 256,000 instruction cycles/s |
| 内部ROM | 8 KiB `0000..1fff` |
| バンクROM | 16 KiB×4、窓 `4000..7fff`、選択 `3c00` の下位2bit |
| legacy形式 | `pc1460mem.bin`（8 KiBまたは64 KiB、先頭8 KiBのみ使用）＋ `pc1460bank.bin`（64 KiB、bank 0..3順） |
| `.pgrom` | `internal`＋`bank-0`..`bank-3`。各bankは16 KiB |
| RAM | 固定32 KiBカード相当 `8000..ffff`。容量選択なし |
| 制御窓 | `2000..3fff`、LCD／selectorを含む互換窓。物理RAM容量とは区別 |
| キー | `3e00` の最下位set bitでgroups 0..6、IAでgroups 7..12。INB=`00` |
| BASIC | 1450と同じS1語彙・カナ形式。text初期 `8030`、pointer `ff01..ff04` |

BASIC writerの上限はpointer手前 `ff01` exclusiveとするソフトウェア境界。
実機ROMの変数／作業領域を含む最大空き容量は未確定で、全域をBASICとして使えると主張しない。
RAM拡張・カード差・外部I/Oを推測で追加しない。

## LCD配線と表示比率

LCDは24桁×1行、**論理5×7 dot**。細長さを論理ドット数へ混入しない。

| アドレス（両端inclusive） | 論理columnの順序 |
|---|---|
| `3000..301d` | 0..29 |
| `302d..303b` | 30..44 |
| `301e..302c` | 45..59 |
| `305e..306c` | 74..60 |
| `306d..307b` | 89..75 |
| `3040..305d` | 119..90 |

symbolは `303c`（カナ／小／SML／STAT／MATRIX）、`303d`（BUSY／DEF／SHIFT／HYP／PRO／RUN／CAL）、
`307c`（E／M／括弧／RAD／G／DE／PRINT）。
Studioの物理dot pitchの横:縦は **3:4**。参照MainLoop1460のstep x=3/y=4から採る。
1450／1470Uの正方形pitchと別にし、Coreのsnapshotは5×7のまま。
これは参照UIとの一致で、実機LCD寸法の精密測定とは区別する。

キーmatrixは確認済みの1450共通部分を使う。FSEと統計切替キーは参照GOで欠落していたため、ローカルROMで補完位置を検証した。
関数キーはユーザー提供の実機画像に合わせた6列×3行（18キー）。F↔E位置はFSE、2行目右端は通常「↕︎」、SHIFT刻印はSTAT。MATRIXはSHIFTの上下キーであり独立キーを推測追加しない。

## 確認の区分

- 合成: 4バンク全て、selector mask／隣接address／reset／イベント／ROM write保護、CPUからの切替と選択bank実行、LCD各区画端／symbol、キー／BRK、BASIC／メモリ境界。
- ローカルROM: 起動時 `MEMORY ALL CLEAR O.K.?` をY／ENTERで確認後、CAL／RUN／PRO切替、BASIC直接ロード、FACT(5)とPOKEによる120の書込み、ERRORなし。
- 初期化確認への入力はテスト内だけ。Studioは勝手にY／ENTERを入力しない。
- パッケージ・Studio keyboard・Project starter・物理比率は自動検証。実機／Windowsユーザー操作／最大容量は別の未確認項目。
