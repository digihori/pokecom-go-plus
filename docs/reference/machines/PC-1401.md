## 2026-10-14 更新: PC-1401 / PC-1402共通シリーズ

今回のユーザー合意は、機能仕様をシリーズ共通、機種差をユーザーメモリ容量として扱う方針。
外部ROMの違いはROM版差として受け入れ、既知ROM hashやhook addressで制限しない。
以下の旧調査の「1402を容量違いとして扱わない」という保留判断は、この方針で更新する。

| 項目 | PC-1401 | PC-1402 |
|---|---|---|
| Machine ID | `pc-1401` | `pc-1402` |
| 物理外部RAM | `3800..47ff`（4 KiB） | `2000..47ff`（10 KiB） |
| BASIC既定開始位置 | `3800` | `2000` |
| start/end pointer | `46e1..46e4` | 同左 |
| CPU / LCD / キー / BASIC | 既存1401実装を共用 | 同左 |

BASICロードでは有効な初期化済みpointerを尊重し、未初期化なら機種別既定位置を使用する。

PC-1401/1402のBASIC置換成功時には、CPU内部RAM `0x35` のbit `0x10`
（旧RUN位置への編集復帰状態）を解除する。残したままだと、短縮ロード後も上キーで
カーソル付き編集へ入り、CL後も不正なカーソル位置を再利用する。
これはPC-1245の内部RAM `0x15` とは別の位置。失敗・BASICなしのメモリロードでは変更しない。
PC-1401/1402のローカルROMで、手入力した短いBASICの行表示を期待値として回帰確認した。
writer上限は既存の`46e0` exclusive。容量依存RAMミラーの追加は対応を保留し、
従来LCDミラーは維持する。Expanded RAM／メモリーカード拡張は今回追加しない。

Studioでは機種選択と入出力を接続し、ROM Libraryは既存の`pc-1401/active.pgrom`をシリーズ共用とする。
Player新機種選択・skinとProject互換方針は変更しない。

合成・Studioテストで任意ROM byte列の受入れ、容量別RAM境界・BASIC・reset・package identityを検証する。
ローカル1401 ROMで1401のNEW／BASIC実行を確認。手元の同ROMを1402のRAM配置で動かすと
NEW後も3800を使ったため、全ROM版の別容量自動認識を確認したとは扱わない。
1402用ローカルROMは未提供で、実ROM確認は残る。ROMをpatchしたり強制hookを加えたりしない。

追加出典: [RAM交換による1401の10 KiB化実験](https://hw-by-design.blogspot.com/2018/07/sharp-pc-1401-memory-mod.html)。
旧調査資料は以下に履歴として残す。全体方針・検証結果は[PORTING_NOTES](../../development/PORTING_NOTES.md)の最新記録を参照。

## 2. CPU / ROM / RAM

- CPUはSC61860A08。既存の`Sc61860Cpu`、命令decoder / assembler / debuggerを共用する。
  CPU専用命令の追加が必要という根拠は今回見つかっていない。
- 内部ROMは8 KiB、`0000..1fff`。外部ROMは32 KiB、`8000..ffff`。計40 KiB、bankなし。
- 旧`pc1401mem.bin`は64 KiBのアドレス空間image。ROM component importerは
  上記2領域のみ抽出し、RAM / LCD / holeの内容は破棄する。PC-1261 / 1350と同じROM layoutを使えるが、
  `MachineId("pc-1401")`は独立させ、他機種のROMをサイズ一致だけで同一視しない。
- 回路図には固定2 KiB RAMに加え、PC-1401用2 KiB / PC-1402用8 KiB RAMが示される。
  外部RAM総量は1401が4 KiB、1402が10 KiB。CPU内部RAM、LCD register RAM、
  BASICで利用可能な容量をこの総量へ混ぜない。製品表記の4.2 / 10.2 KBとの換算も別途確認する。
- MAMEの配置を物理busの第一候補とする。

| Range | PC-1401候補 | PC-1402参照との差 |
|---|---|---|
| `0000..1fff` | 内部ROM、読出し専用 | 同じ窓 |
| `2000..37ff` | 未実装領域、RAMとして公開しない | 1402では追加RAM |
| `3800..47ff` | 4 KiB RAM | 1402と共通の窓 |
| `4800..5fff` | 未実装領域 | MAMEでは同じ |
| `6000..67ff` | LCD register aperture | MAMEでは同じ |
| `6800..6fff` | 未実装領域 | MAMEでは同じ |
| `7000..77ff` | LCD aperture mirror候補 | MAMEでは同じ |
| `7800..7fff` | 未実装領域 | MAMEでは同じ |
| `8000..ffff` | 外部ROM、読出し専用 | 同じ窓、内容共通とは未確定 |

MAMEのLCD read/writeは`offset & 0xff`で256-byte registerへ正規化する。
aperture内の繰返し、`7000`側mirror、未接続領域の読出し値は実ROM / 回路図のdecodeで検証する。
Pokecom GOは`2000..7fff`を広くRAMとして扱い、LCDも特定アドレスだけ更新する。
この24 KiB書込み窓を実機RAM仕様として移植しない。解析用書込みを許可する場合も、
物理busとは別の明示的なhost機能として判断する。

発振クロック576 kHzを3 clocks/cycleで換算し、192,000 cycles/sを基準とする。
2026-10-11の全機種監査でPockEmulの576,000/3定義と照合した。
CPUの公称2 ms / 500 ms dividerは384 / 96,000 cycles、ブザーも192,000 cycles/sで換算する。
以前の288,000という仮説は撤回。出典と残るハードウェアタイマー検証はPORTING_NOTESを参照。

## 3. LCD

16文字 × 1行、各文字5×7 dots、論理80×7。文字間gapは1列。
LCD driverはSC43536。Pokecom GOとMAMEは以下の配置で一致する。

- 左8文字: `6000..6027`を順方向。
- 右8文字: `6067..6040`を逆方向。
- `603c` bit 3: STAT。
- `603d` bits 0..6: BUSY, DEF, SHIFT, HYP, PRO, RUN, CAL。
- `607c` bits 0..6: E, M, 括弧, RAD, G, DE, PRINT。
- OUTC bit 0によるdisplay enableは既存のI/O境界を使う。

`Pc1245Display`とは文字数と表示後半の並び方が異なる。Snapshotとdots変換の設計は共用し、
物理register配置とsymbol mapは`Pc1401Display`へ置く。
`DisplaySymbol`にCAL / HYP / STAT / M / 括弧の状態を追加し、E表示の意味・既存ERRORとの対応を確認する。
Studio / Player双方でsymbol labelと表示順を確認する。RUN/PROをhost状態から合成して
ROMのCAL表示と矛盾させない。

## 4. キーマトリクスとモード

Pokecom GOは14 groups × 8 bits。IBの下位7bit用前半7 groupsの最後は空、
IAの下位7bit用後半7 groupsを持つ。MAMEでは空groupを除いた13 groups。
通常の1bit選択のキー配置は一致するが、読取りアルゴリズムは異なる。

- Pokecom GO: IAが0ならIB、IAが非0ならIA側を優先し、最下位選択bitのgroupだけ返す。
  INBは常に0。
- MAME: IA自身を基礎にし、IA / IBの全選択groupをORする。INBはIB latchとpower状態を返す。
  初回起動ではC-CE押下を一時的に模擬する。
- 回路図のIA / IB接続を根拠に専用`Pc1401Keyboard` / Ioを実装し、単bit、複数bit、
  IA/IB同時、同時押し、BREAK/KON、power-upを検証する。起動専用C-CE模擬は必要性確認前に追加しない。

選択とキー配置（列内はbit 0から7、`-`は空）:

| Select | Keys |
|---|---|
| IB0 | +/- 8 2 5 CAL Q A Z |
| IB1 | . 9 3 6 BASIC W S X |
| IB2 | + / - * DEF E D C |
| IB3 | ) ( x² √ y^x EXP X→M = |
| IB4 | STAT切替 1/x LOG LN DEG HEX - M+ |
| IB5 | C-CE F↔E TAN COS SIN HYP SHIFT RM |
| IB6 | - - - - - - - - |
| IA0 | - 7 1 4 DOWN R F V |
| IA1 | - - , P UP T G B |
| IA2 | - - - O LEFT Y H N |
| IA3 | - - - - RIGHT U J M |
| IA4 | - - - - - I K SPACE |
| IA5 | - - - - - - L ENTER |
| IA6 | - - - - - - - 0 |

CAL / RUN / PROの3状態を扱う設計とする。CAL / BASICはマトリクス内の物理キーであり、
既存機種のmode switch RAM値を流用しない。BASICのRUN/PRO遷移とcold / warm reset時の状態は
ROMと取扱説明書で確認する。RESERVEは対応させない。STATは別の`OperatingMode`に増やさず、
ROMが制御する電卓内状態とLCDシンボルとして扱う。

`PocketKey`へCAL / BASICと不足する関数キーを意味単位で追加する。
既存LEFT_PAREN / RIGHT_PARENなどは共用可能。関数は文字列やAndroid resource IDでcoreへ渡さない。
`OperatingMode.CALCULATOR`を追加し、PC-1401の`setOperatingMode`はLCDから状態を判定して
cycleベースのCAL / BASICキー入力を要求する設計を検討する。ROMワークRAMへ値を直書きしない。
入力sequenceの実行は既存host queueが担い、coreはthreadや時刻を所有しない。
実行待ち・遷移失敗の表現は既存Unit APIの限界を確認して最小の追加APIで扱う。

## 5. ブザー

音声はOUTCの変化と経過cycleを入力とする既存設計を共用する。
PC-1401ではcycle rateを設定可能にし、ROM内BEEP入口を捕捉して2 kHzを固定長で鳴らす
Pokecom GOのhookは採用しない。MAMEはMACHINE_NO_SOUNDで、音声照合先として使わない。
BEEPの回数 / 音高 / 無音区間、OUTC oscillator mode、TEST dividerの時間を確認する。
スピーカー出力とPCM再生はhost側に残す。

## 6. BASICと保存形式

OLDのPC-1245 / 1251とは異なるS1系。PC-1261 / 1350とRAM内の行フレームを共用できる。

`FF [line-hi line-lo length body... 0D]* FF`

行番号はbig endian、lengthは行末0Dを含む1 byte。文字はASCII系、keywordは1 byte。
OLDの3桁packed decimalや独自英数字コードを使わない。S2のFE keyword prefixも使わない。
特殊文字の`FB..FE`（参照表のPI / SQR / INS / BX）はROM出力で確認し、
PC-1261 tokenizerのFE半角カナ経路を無条件に有効にしない。

PC-1401 / 1402の参照token tableは一致。
PC-1261にない`81..90`のREC, POL, ROT, DEC, HEX, TEN, RCP, SQU, CUR,
HSN, HCS, HTN, AHS, AHC, AHT, FACが必要。
逆にPC-1261のCLS / CURSOR (`CE/CF`)はPC-1401参照表にない。
PCWAVの表にあるOPEN / SAVE / LOADやgraphics命令もPC-1401へ持ち込まない。
`Pc1401BasicTokenizer`は専用語彙を持たせ、共通S1行処理を明示的な設定へ抽出する。
PC-1350名のresult型を新規機種へ拡散させるかは整理範囲を小さく判断する。

Pokecom GOのRAM管理候補:

- program default start `3800`。
- start pointer low/high `46e1/46e2`。
- end pointer low/high `46e3/46e4`。
- PC-1402のActivityもdefault `3800`を使う。追加RAMをBASICでどう利用するかの証拠にはならない。

`Pc1401BasicProgramMemory`はROMでNEWした直後・1行入力後・削除後のpointer、
開始/終了FFを含む範囲、変数/配列との衝突を確認してからload / extractを確定する。
容量を単純に`46e1 - 3800`で決めない。S1 transfer payloadのtrailer FFとRAM program envelope、
PGP project artifact、`.dmp`のaddress付き形式はそれぞれ分離する。
WAVのS1 codecはPGPではまだ仕様調査段階であり、PC-1401追加と同時に完成させる前提は置かない。
