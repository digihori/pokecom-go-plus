# MCP対応AIクライアントへのAI連携拡充計画

更新日：2026-11-02

**2026-11-02 中断中。再開は[中断・再開メモ](AI_MCP_RESUME.md)から。**
現状・CALLの未解決事項・残作業・機種展開の暫定見積もりを記録している。

ステータス：開発方針を合意。以下の追加機能と受入れ検証は計画であり、実装済みを意味しない。
現行APIは[AI連携仕様](../reference/AI_INTEGRATION.md)、接続方法は

## 1. 大方針と利用者の目標

- 対応範囲を「Claude対応」から「MCP対応AIクライアントへの対応」に広げる。
- 機能開発と日常の動作確認はCodexを主に使い、Copilotなどの別クライアントで相互運用を検証する。
- AIごとに機種知識や操作処理を複製せず、Studioの共通Application ServiceをMCP経由で公開する。
- Claudeのアカウント取得や有料契約を、開発開始の前提にしない。

デスクトップ版Studioをインストールした利用者が、外部AIを接続して次の二つを行えることを目標とする。

1. 自作または既存のポケコンプログラムを解析する。
2. 要求仕様から新しいポケコンプログラムを生成し、動作を確認する。

ポケコン固有の知識はアプリ側で保持し、MCPから必要な部分を検索・取得できるようにする。
利用者による開発リポジトリの取得や、AI専用の指示ファイルの準備を必須にしない。
AIサービスの認証はクライアント側で扱い、StudioはAIベンダーのSDKや資格情報に依存しない。

## 2. 計画開始時点の現状

現行の公開MCPツールは15件。機種仕様、ソース、逆アセンブル、Trace等の取得と、
Studio承認付きのソース差分、Build、Load、デバッグ操作、現在PCからのContinueを提供している。
新規Project作成、キー入力、LCD画像取得、自動の実行上限は未対応。
ContinueはBASICのRUNやCALLを入力する操作ではない。

機種知識は命令一覧やメモリ配置などが中心で、ROMルーチンの呼出規約やキー入力処理等は不足している。
実装にはPC-1245のLCD直接描画情報があるが、他機種も同じ仕様とは扱わない。
実装済み機能、自動検証済みの範囲、外部クライアントでの受入れ結果は区別する。

## 3. 開発順と完了条件

最初は検証実績のあるPC-1245を対象候補とし、1機種で解析・生成の流れを完成させてから対応機種を増やす。

| 段階 | 実施内容 | 完了条件 |
| --- | --- | --- |
| 1. 現状整理・共通課題 | 現行15ツール、不足機能、解析・生成の受入れ課題を整理 | 入力、期待結果、判定方法が決まっている |
| 2. クライアント共通化 | 汎用の接続案内、認証、設定生成を整備し、必要に応じてstdioブリッジを追加 | Codexと別クライアントで情報取得・承認往復が成功する |
| 3. 機種知識の拡充 | 機種別仕様、資料、検証済みサンプルの検索・取得 | リポジトリを直接読まずに課題に必要な知識を取得できる |
| 4. 既存プログラム解析 | 利用者が選択したソース・バイナリの取り込みと解析情報を整備 | 根拠と不明点を伴う解析結果を提示できる |
| 5. 新規生成 | Project作成、生成、Build、Load、起動、表示確認、修正をつなぐ | 要求から動作確認までStudioとMCPで完結する |
| 6. 機種展開・配布確認 | 機種別知識・作例を追加し、配布版で検証 | インストール後の利用者が公開手順に沿って利用できる |

### 共通の受入れ課題

| 課題 | 内容 | 主な判定項目 |
| --- | --- | --- |
| BASIC解析 | 小さな既存ソースの処理内容、入出力、変数の役割を説明 | ソースに基づく説明、機種方言の照合 |
| 機械語解析 | 開始アドレスを指定した小さなバイナリを逆アセンブルと実行観測で解析 | 制御フロー、使用メモリ、観測根拠、未確認事項 |
| 新規生成 | キー入力で表示を切り替えるプログラムを要求仕様から作成 | Project作成、Build、起動、期待表示・入力、修正後の再確認 |

課題ごとに入力データ、機種・ROM条件、期待結果、確認手順を記録する。
AIの回答文の一致ではなく、必要な情報取得、正しいBuild、期待動作、根拠の提示で判定する。
ソース付きとバイナリのみの解析は区別し、任意の大規模バイナリの完全解析を初期の完了条件にしない。

## 4. クライアント共通化

最初の別クライアント候補はGitHub Copilot＋VS Codeとする。Gemini CLI、Claude Desktop、
Claude Code等も候補とし、製品単位で接続方式と認証条件を確認する。
通常のブラウザチャットも同じ機能を持つとは扱わない。

最初に現行機能で「接続→機種仕様取得→ソース取得→変更提案→Studio承認→結果取得」を試し、
短期トークン、通信、応答形式の差を洗い出す。その結果に基づき設定生成と必要なブリッジを実装する。

stdioブリッジを追加する場合は通信・認証の中継に限定し、機種知識と操作処理は共通サービスを使う。
利用者に別途Node.jsやPythonの導入を求めない同梱形態を目指す。
アプリ再起動後の短期トークン更新にも対応する。

| 対応状況 | 意味 |
| --- | --- |
| 対応候補 | 必要なMCP接続機能がある。PGPとの接続は未確認 |
| 接続確認済み | 情報取得とStudio承認往復を確認済み |
| 用途検証済み | 共通の解析・生成課題を完了済み |

結果にはStudio版、クライアント版、OS、接続方式、実施日、確認範囲を残す。
MCP対応の表明や自動プロトコルテストだけで、特定クライアントを検証済みとは扱わない。
クライアントの料金・利用制限は変わり得るため、検証時に公式情報を確認する。

## 5. 機種知識の提供

優先順は次のとおり。

1. BASICの機種別構文・文字コード・制限と内蔵assembler構文
2. CPU命令の動作・フラグへの影響とメモリ配置・BASICとの共存条件
3. LCD表示、キー入力、プログラムの起動方法
4. 適用条件と確認手順を持つ検証済みサンプル
5. ROMルーチンの呼出条件、引数、戻り値、破壊レジスタ

各項目は対象機種、ROMの適用条件、出典、検証状態を持つ。
エミュレータ実装由来、資料記載、実ROM確認、実機確認を区別し、未確認事項を明記する。
既存のCore定義から取得できる情報は共用し、別の仕様表との不整合を防ぐ。
資料・サンプルの同梱時は出典と配布条件を確認し、ROM本体を同梱しない。

追加する読み取りツールの候補（名称・schemaは未確定）：

- `pgp_search_knowledge`：機種・話題・キーワードで検索する。
- `pgp_get_knowledge`：項目IDから本文と出典を取得する。
- `pgp_get_example`：適用条件と確認手順を含む作例を取得する。

重要情報はToolsから取得可能にし、Resourcesを追加する場合も同じ情報源を参照する。
初期は機種・話題・命令名の索引を優先し、大規模な検索基盤を前提にしない。
検索・本文取得にはページングやサイズ上限を設け、全資料を暗黙に送信しない。

## 6. 解析・生成を完成させる機能

解析では、利用者が選択したソース・バイナリをStudioに取り込み、機種、ロード位置、入口、
既知の情報を付けられるようにする。AIは必要な逆アセンブル、Memory、Traceを追加取得する。
結果は確認できた事実、推定、未確認事項を区別する。

生成では、以下の不足機能を追加する。

- Project・Sourceの新規作成提案
- BASIC RUN／CALL・キー操作による起動
- 命令数・サイクル数を制限した実行と停止結果の取得
- LCD画像・表示状態の取得

目標の流れは「仕様確認→生成→Build→Load→起動→結果確認→修正」。
既存のStudio側承認、Session／Projectの照合、revisionによる古い操作の拒否を維持する。
任意ファイルアクセスや無制限のROM送信へ拡張しない。

## 7. 検証と配布

日常の開発はCodexで行い、別クライアントでは接続整備時と解析・生成完成時に共通課題を実施する。
毎回すべてのAIで試すことは必須にしない。プロトコル、認証、承認前の無変更、古いrevisionの拒否等は
自動検証で支え、実クライアントの受入れと区別する。

リリース前には、開発環境への依存を除いた配布版で、アプリのインストール、必要なROMの登録、
AIクライアントの接続、解析・生成までを公開手順に沿って確認する。
新規課金を必須にせず、利用可能なアカウント・無料枠での検証も選択肢とする。

## 9. Stable／Technical Previewの配布方針（2026-11-02合意）

AI連携は機能を少しずつ追加し、Technical Previewで先行提供する。
通常利用向けの正式版はStableとして維持する。全機種・全クライアントへの展開を
最初のプレビューの条件にせず、確認できた範囲を明示して配布する。

| 区分 | 位置付け |
| --- | --- |
| Stable | 従来機能も含め、所定の受入れ確認を終えた通常利用向けの正式版 |
| Technical Preview | AI連携の新機能を先行提供する開発途中の版。対応範囲・制限・既知の問題を明記 |

プレビューはGitHub ReleasesのPre-releaseとして識別する運用を予定する。
バージョン表記の候補はvX.Y.Z-preview.Nとし、具体的な番号・タグ・公開日は
既存の採番と配布フローを確認して配布準備時に決める。現時点で公開は指示されていない。

### 作業単位と受入れ

- 各プレビューは小さな到達点で区切る。例：PC-1245解析・生成、Copilot全工程確認、長いソースの部分取得。
- リリースノートへ、機能・機種・クライアント別の実装済み／検証済み、既知の問題、未検証範囲を記載する。
- 初回はPC-1245を主な検証対象、PC-1251を試験対応とする。
- 初回配布候補の区切りはCopilotの新規チャットでの解析・生成全工程の受入れ完了とする。
  PC-1251 CALLの未解決事項は調査し、残る場合は制限を明記する。
- プレビューも全体ビルド・テスト、配布物のインストール／起動、既存Projectの基本操作を確認する。
- 確認できた機能を順次Stableへ取り込む。Stable／AI版を長期間別製品として維持することは目標としない。

### 互換性と配布準備

Project形式・設定の互換性を維持し、Stableへ戻る条件を明確にする。
同時インストールはまだ実装・保証していない。必要性を配布準備で判断し、採用する場合は
アプリ識別子、設定・データ保存先、MCPポート・認証ファイル、更新経路の競合を確認する。
正式版の上書きや設定分離が自動的に解決済みとは扱わない。

最初のプレビューは作業ブランチcodex/ai-mcp-expansionを起点に準備する。
恒久的なreleaseブランチの構成やCI変更は、既存のリリース手順を確認して決める。
今回の合意は開発・配布方針の決定であり、タグ作成・Release公開・Stableへのマージは未実施。
