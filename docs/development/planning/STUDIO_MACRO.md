# Studioマクロ 初版の機能仕様案

2026-11-08。利用者との検討内容をまとめた実装前の仕様案。
初版は基本3命令（load／mode／cmd）とwait／key／pause、強制中断を対象とする。
以下の構文・UI・操作制限は初版に向けた提案であり、実装済みではない。

## 目的と実行方法

Studio操作とエミュレータへの入力をテキストファイルに記述し、上から順に実行する。
マクロファイルを選び、「マクロ実行」で開始する。同時に実行できるマクロは1件。
現在選択しているエミュレータを対象とし、機種・ROMの自動切替は行わない。
Projectを開いていなくても、利用できるロード経路の範囲で実行できる構成を目指す。

起動経路は「マクロ」メニューの「マクロを実行…」によるファイル選択と、
Project内の`.pgmacro`選択後の「マクロ実行」ボタンの2通りを用意する。
「マクロ」メニューには実行・再開・中断を置き、実行中は新規実行を無効にする。
再開はpause中のみ、中断は実行中・待機中のみ有効にする。

## Project操作改善と合わせた作業順（提案）

1. Projectへのファイル登録とBuild／Load対象を分離し、複数BASICの登録を可能にする。
2. 選択ファイルのBuild／Build & Loadを用意する。複数選択時もBASICは最大1件とし、配置重複を検査する。
   全体操作は対象を明示し、複数BASICがある場合は対象選択を案内する。ロード状態は実際の対象に合わせる。
3. Project作成、ファイル新規作成、既存ファイルの複数追加、名前変更を改善する。
   空のProject作成を可能にし、ファイル操作とManifestを同期する。マクロはBuild対象に含めない。
4. メイン画面下部のコンソールを追加する。
5. 手動操作と共通のロード処理を使ってマクロ実行処理を実装し、メニュー・Project操作へ統合する。
6. Project作成から複数ソース追加、個別ロード、マクロ実行まで通して確認する。

名前付きのBuild／Load対象、複数Projectの作業セットは、この一連の改善後に必要性を再検討する。

## ファイル形式（提案）

- UTF-8のテキスト。拡張子は`.pgmacro`を提案する。
- 1行1命令。空行と、行頭の空白を除いた先頭が`#`のコメント行を許可する。
- 命令名・モード名・キー名は大文字小文字を区別しない。
- 文字列・パスは半角の二重引用符で囲む。文字列内の`\"`と`\\`を引用符・バックスラッシュとして扱う。
- 相対パスはマクロファイルのあるフォルダを基準とする。空白・日本語を含むパスを扱えること。
- 開始前にファイル全体の構文を検査する。未知の命令・不正な引数は行番号付きで報告し、実行を開始しない。

## 初版の6命令

| 命令例 | 動作 |
| --- | --- |
| `load "xxx.dmp"` | Studioの既存ロード処理で指定ファイルを現在のエミュレータへロードし、処理完了を待つ。初版は少なくともBASICテキスト（`.bas`）とマシン語ダンプ（`.dmp`）を対象とする。ビルドはしない |
| `mode PRO` | 指定モードへ切り替える。少なくともPRO／RUNを対象とし、機種が対応しないモードはエラー。同じモードなら成功 |
| `cmd "CALL &C000"` | 文字列をエミュレータへ入力し、最後にENTERを送る。ENTERの送信完了後に自動で1秒待ってから次の命令へ進む。起動したプログラムの終了は待たない |
| `wait 500ms` / `wait 2s` | 指定時間待つ。待機中もエラー監視と強制中断を受け付ける |
| `key ENTER` / `key BREAK` | 指定キーを1回押して離す。初版の具体的な対応キーは既存の機種別入力APIに合わせて一覧化する。未対応キーはエラー |
| `pause "結果を確認してください"` | メッセージを表示して利用者の「再開」を待つ。「中断」も選べる。エミュレータの実行は継続する |

`mode`と`load`の完了は、プログラムの正常終了やコマンド受付可能を意味しない。
ロード時のモード変更・既存BASICの置換など、既存ロード処理の副作用は実装時に確認して明記する。
`NEW`や起動コマンドをマクロ実行側が勝手に追加しない。
`cmd`は入力不能な文字を事前検査し、送信途中の失敗時には後続操作を止める。
`cmd`の自動待機1秒間もエラー監視と強制中断を受け付ける。
この待機はマクロ末尾の`cmd`にも適用する。1秒はホスト側の経過時間とし、
処理の正常終了・コマンド受付可能を保証しない。さらに待つ必要がある場合は`wait`または`pause`を続ける。

## エラー時の動作（合意事項）

- エミュレータがエラーを示した場合、マクロをエラー中断する。
- ファイルの読込み・ロード、モード切替、入力送信などStudio側の操作でエラーになった場合も、エラー中断する。
- 後続命令は実行しない。自動リトライ、エラー無視、自動消去は初版では設けない。
- マシン語起動後の暴走は自動検出できない。エラーがないことを正常終了とはみなさない。

### 検出・表示の仕様案

- エミュレータのROMエラー状態とCoreの異常状態を、命令実行中・wait中・pause中に監視する。
  マクロ終了後は監視対象外とし、起動したプログラムの成功を保証しない。
- ROMエラー検出は既存のERROR表示等を利用し、機種ごとの対応可否を確認する。
  判定できない機種を黙って対応済みにせず、初版の対応機種・制限を明示する。
- 開始時点で既にエラー状態の場合も実行を開始しない。
- ファイル名、行番号、命令、停止理由を表示する。エラー番号は取得可能な場合のみ付記する。
  非同期に発生したROMエラーは、直前のcmdが原因とは断定せず、検出時の行と直近の送信内容を記録する。
- エラー画面・メモリ・モードはそのまま保持し、実行済み操作を巻き戻さない。

## 強制中断（初版必須）

- 実行中は常に「マクロ中断」を利用できる。wait／pause／文字入力／ロード待ちでも受け付ける。
- 中断要求後、新たな命令・キー入力を送らない。マクロが押下中のキーは解放する。
- 既に始まった取消不能のロード等は安全に完了させ、後続命令へ進まない。
  UIを長時間ブロックせず、中断処理中であることを示す。
- マクロ中断はエミュレータへのBREAK送信やResetとは別の操作とする。
  暴走したマシン語を停止する場合は、Studioの既存のエミュレータ停止・Reset操作を使う。
- 利用者による中断とエラー中断を表示・ログで区別する。途中再開は初版の対象外。

## 実行UIと競合操作（提案）

### メイン画面下部のコンソール（2026-11-08追加）

- メイン画面の下側に、マクロなどStudio操作の経過・結果を表示するコンソールを追加する。
  エミュレータのLCD表示とは別の、読取り専用ログ表示とする。
- 表示メニューの「コンソール」で表示ON／OFFを切り替える。マクロ実行開始時は自動でONにする。
  構文検査など開始前のエラーも自動表示して理由を示す。
- 実行中でも非表示にできる。非表示はマクロの停止・ログの消去を意味しない。
  エラー中断時は再び自動表示する。正常完了時は利用者が選んだ表示状態を維持する。
- コンソールには実行開始、対象マクロ、行番号・命令、pause待機、再開、完了、
  エラー中断、利用者中断を表示する。cmdは送信内容を表示する。
  エミュレータ内のプログラム出力やLCD文字列の自動転記は初版の対象外。
- 「ログ消去」と、実行中の「マクロ中断」、pause中の「再開」を設ける。
  非表示中もメニューから再開・中断できるようにする。
- 上端をドラッグして高さを調整できるようにし、高さと手動の表示設定を保存する。
  マクロによる一時的な自動表示は、保存済みの手動設定を書き換えない。
- ログはスクロール可能とし、末尾表示中のみ追従する。文字列の選択・コピーを可能にする。
  ログ保持量には上限を設け、古いものから破棄する。上限値は実装時に決める。
- 将来はBuild／Load等の操作ログも同じコンソールへ集約できる構成とする。
  初版ではマクロと、そこから呼び出したStudio操作の結果を必須範囲とする。

### 実行操作

- 実行状態、現在の行・命令、実行ログ、pauseの再開、マクロ中断を表示する。
- 通常のキーボード入力や手動Load・モード切替など、マクロと競合する操作を実行中は抑止する。
  pause中は必要な手動入力を許可し、利用者が明示的に再開する。
- 機種・ROM・Projectの切替は実行中に抑止する。エミュレータ停止・Resetは利用でき、使用時はマクロも中断する。
- 最終状態は完了／エラー中断／利用者中断を区別する。「完了」は命令列の処理完了を意味する。

## ユースケース

単純なマシン語起動：

```text
cmd "CALL &C000"
```

PROモードで初期化と特殊コマンド入力を行い、マシン語をロード：

```text
mode PRO
cmd "NEW"
cmd "EQU #43"
load "xxx.dmp"
```

BASICソース1を実行し、利用者が終了を確認してからソース2へ入れ替える：

```text
load "basic1.bas"
mode RUN
cmd "RUN"
pause "プログラムの終了を確認して再開してください"
mode PRO
cmd "NEW"
mode RUN
load "basic2.bas"
```

各`cmd`の後には自動で1秒待つが、全機種・全処理で十分な時間を保証しない。
初版では処理終了の自動判定を行わず、固定時間のwaitまたはpauseを使う。

## 初版の受入れ項目

- 3つのユースケースが対応機種で実行できる。
- 各cmdはENTER送信完了後に1秒待ち、末尾のcmdも待機・エラー監視・強制中断の対象となる。
- 構文不正、ファイル不在、ロード失敗、未対応モード・キー・文字で適切に停止する。
- ROMエラーを検出すると後続のNEW／loadへ進まず、停止理由が分かる。
- wait／pause／入力送信中に中断でき、後続命令が走らず、キーが押しっぱなしにならない。
- エミュレータでマシン語が暴走していても、マクロの中断操作を受け付ける。
- 取消不能操作の完了後にも中断要求が維持され、後続命令へ進まない。
- 実行後・中断後に再びマクロを開始できる。二重実行を防ぐ。

## 初版以降の追加検討

| 項目 | 検討内容 |
| --- | --- |
| `wait ready timeout=30s` | 正常なコマンド受付状態への復帰待ち。BUSY消灯だけに依存せず、INPUT待ち・キー待ち・ROMエラーとの区別を機種別に調べる。タイムアウトは暴走の断定とは区別する |
| 完了条件の指定 | メモリ値・表示内容などでプログラム固有の完了／失敗を判定する |
| `build`と成果物ロード | Studioの内蔵／外部Assembler等でビルドしてからロードする |
| マクロの共通化 | include、引数、変数、条件分岐、繰り返し。具体的な用途を確認して導入する |
| メモリ保存 | エミュレータ上で生成したマシン語を指定範囲からファイルに保存する |
| 実行前提の確認 | 機種・ROM・RAM構成のチェック、Projectや作業セットとの関連付け |
| 入力操作の拡張 | 長押し・同時押し・キー列、機種別の追加モードやキー |
| 編集・実行支援 | マクロ編集、最近使ったマクロ、行単位実行など |
| 詳細な診断 | 機種別のエラー番号取得、ログ保存、エラー検出の対応機種拡大 |
