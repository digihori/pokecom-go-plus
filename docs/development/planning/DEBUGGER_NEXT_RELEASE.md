# 次のリリースに向けたDebugger強化

開始日：2026-10-30。mainから分岐して作業します。
対象はStudioです。WAVデバッグ、Assembler周辺、BASIC入出力チェックは別の作業として管理します。

## 出発点

ソース連携、条件付きBreakpoint・ヒット回数、限定的なStep Over／Out、
対象照合付き設定保存・復元は実装済みです。既存機能の再実装ではなく、
受入れと追加機能を分けて進めます。未確認は不具合確定を意味しません。

## 作業順と完了条件

| 順序 | 作業 | 完了条件 |
| --- | --- | --- |
| 1 | 既存機能の受入れ・修正 | 自動テストの基準結果を記録し、下記の操作を確認。不具合は再現条件・修正・回帰検証を記録 |
| 2 | メモリ検索 | 停止中Snapshotから範囲指定のbyte列・数値検索。読み取り不可領域、bank、上限を明示し、結果からMemory Viewへ移動 |
| 3 | RAM編集 | 停止中の書込み可能RAMをbyte単位で編集。範囲と値を検証し、失敗時は状態を維持。監視・差分・ソース対応を更新 |
| 4 | ログポイント | 停止せず位置・指定値を記録。条件、記録上限、破棄規則を定義し、実行負荷を確認 |
| 5 | 履歴・Trace出力 | Checkpointとは独立して出力。位置・bank・停止理由等の項目、形式、上限を定義して検証 |
| 6 | bank指定Breakpoint | 論理アドレスが同じ別bankを区別。登録UI・設定保存・MCPの整合を検証 |
| 7 | Step Over／Outの対応拡大 | CASE・未観測スタック等を調査。追跡可能な範囲だけを追加し、追跡不能時の停止を検証 |
| 8 | 操作性・文書・環境別確認 | 日英表示、狭い画面、キーボード操作、macOS／Windows／Linux配布アプリの結果と制限を記録 |

6・7は調査結果から採用範囲を決めます。複合条件式、Checkpoint自動比較、
過去状態への巻戻しは後続候補です。各段階の仕様・検証後に次へ進みます。

## 既存機能の受入れ項目

- [x] Core／Studioの既存自動テストを実行し、成功・失敗・skipを記録する。
- [ ] Continue／Pause／Step／Run To、停止理由と停止位置への移動を確認する。
- [ ] 条件付きBreakpoint、ヒット回数、無効化・編集、Reset／Load後の回数を確認する。
- [ ] 複数の変更監視・アクセス監視、差分、履歴、bank表示を確認する。
- [ ] Step Over／Outの完了、既存停止条件による中断、上限、追跡不能表示を確認する。
- [ ] ソース移動と外部エディタへの行指定、編集・Load・Reset後の古い対応の拒否を確認する。
- [ ] 設定保存・復元、対象不一致・破損ファイルの拒否、失敗後の既存設定維持を確認する。
- [ ] 入力欄・タブ・ダイアログ操作後のfocusと、エミュレータへの入力漏れを確認する。
- [ ] MCPの登録・Trace・Stepを実接続で確認し、Session／revision変更後の要求拒否を確認する。

## 作業2：メモリ検索の実装結果（2026-10-30）

停止中の範囲指定HEX列／符号なし8・16bit検索とMemory Viewへの移動を実装しました。
現在bankのRAM／ROMだけを検索し、LCD・制御・未割当領域を除外します。
入力・結果上限・古い結果の拒否・CPU／アクセス履歴が変わらないことを検証しました。
日英UI操作を含む全体buildが成功し、Core 500件・Studio 427件で失敗0、条件付きskip 2件です。
[仕様・制限・手動受入れの残項目](../../guides/DEBUGGER.md#20-メモリ検索2026-10-30)を参照してください。
作業1の配布アプリ受入れは継続し、今回の自動検証を手動確認の完了とは扱いません。

## 作業3：RAM編集の実装結果（2026-10-30）

停止中のRAMを1byteずつ、変更前後・物理アドレスを確認して適用するパネルを追加しました。
ROM／LCD／制御／未割当領域を拒否し、Session・revision・現在値を適用直前に再検証します。
成功時はミラーを含む監視の該当byteだけを再基準化し、Breakpointヒット回数を保持します。
Memory Viewの表示・差分を更新し、ソース対応・CALL追跡・ロード済み表示と古いMCP要求を無効化します。
失敗時不変と日英UI操作を検証し、全体build成功、Core 500件・Studio 436件で失敗0、条件付きskip 2件です。
[仕様・制限・手動受入れの残項目](../../guides/DEBUGGER.md#21-ramのbyte編集2026-10-30)を参照してください。

## 作業4：ログポイントの実装結果（2026-10-30）

「登録」タブに、命令位置・記録値・任意の比較条件を指定するログポイントを追加しました。
レジスタ1個／RAM・ROMの1byteを命令実行直前に記録し、ログ自体では停止しません。
最大32登録・256記録で、古い記録の破棄数と読取り失敗を表示します。
Breakpointとの同位置停止・監視・Faultの優先度、Reset／Load、bank、無効時の一括実行経路を検証しました。
日英UI操作を含む全体build成功、Core 500件・Studio 445件で失敗0、条件付きskip 2件です。
[仕様と制限](../../guides/DEBUGGER.md#22-ログポイント2026-10-30)を参照してください。
現行設定ファイルとMCPにはログポイントを追加していません。実ROMの速度・配布アプリの手動確認は残ります。

## 作業5：履歴・Trace出力の実装結果（2026-10-30）

「履歴」タブに、Checkpointと独立した`.pgtrace.json`出力を追加しました。
Trace・アクセス・bank履歴・ログを最新の指定件数で保存し、件数による除外数も記録します。
Trace等は各4096件、ログ256件、出力8MiBまでです。停止理由・物理ROM位置・bank等を保存し、
保存先選択中のSession変更を拒否、一時ファイルからのatomic replaceで保存します。
出力内容、0件・上限、キャンセル・失敗時保持と日英UIを検証しました。
全体build成功、Core 500件・Studio 451件で失敗0、条件付きskip 2件です。
[仕様・出力項目・手動受入れの残項目](../../guides/DEBUGGER.md#23-履歴trace出力2026-10-30)を参照してください。

## 作業6：bank指定Breakpointの実装結果（2026-10-30）

機種のROM切替窓で、論理アドレスと正規化bank番号を指定したBreakpointを実装しました。
別bankは別登録・別ヒット回数として扱い、bank不一致では条件・回数を評価しません。
日英UI、設定v2（旧v1読込み互換）、承認付きMCPの任意bank項目と登録読取りを接続しました。
全体build成功、Core 500件・Studio 458件で失敗0、条件付きskip 2件です。
[仕様と手動受入れの残項目](../../guides/DEBUGGER.md#24-bank指定breakpoint2026-10-30)を参照してください。

## 作業7：Step Over／Out対応拡大の結果（2026-10-30）

現行CoreのCASE命令と未観測スタックを調査し、観測したCASE1の明示的戻り先を追跡する範囲を追加しました。
CASE2の分岐でフレームを保持し、CALL／CASEのネストとRTNを識別します。
未観測スタックからの復元や未モデル化の割込みは追加せず、追跡不能時の停止を維持します。
[調査・設計・検証記録](../DEBUGGER_CASE_STEPPING.md)と[操作仕様](../../guides/DEBUGGER.md#25-case経路のstep-overout2026-10-30)を参照。
全体build成功、Core 500件・Studio 466件で失敗0、条件付きskip 2件です。
配布アプリ・実ROM・各OSの手動確認は作業8とあわせて継続します。

## 共通の検証方針

作業1の[自動検証・修正結果と残る手動受入れ](../DEBUGGER_NEXT_RELEASE_STEP1.md)を記録しました。
既存操作の自動検証は成功しています。以下の未チェック項目は配布アプリ・実ROM・
外部クライアントを含む受入れを残すため、完了扱いにはしていません。

合成プログラムの自動テストと、実ROM・機種・OSごとの手動受入れを区別します。
新しい設定は保存形式・MCPへの影響も点検します。監視・条件・Trace・ログポイントを
併用した場合の実行負荷と記録容量を確認します。ROM由来fixtureは追加しません。
実設定やROM Libraryを使う確認は、隔離した自動検証とは別に記録します。
