## 次の作業：PC-1245の実用BASIC評価

[評価結果と再開点](AI_PC1245_SHOP_QUOTE_EVALUATION.md)に、Copilotの解析と差分提案、Studioでの承認と変更後のLCDを記録した。
PC-1245実ROMでは、ENTER後の間隔を150 msにすると小売とまとめ買いの一括入力が各105通りで期待値と一致した。
この間隔をPC-1245のMCP上限付き実行に適用し、修正後のStudio実行処理でも同じ結果を確認した。
PC-1251 CALLの途中停止後にキー間隔を確保する修正も実ROMで確認した。

1. **題材と期待結果を決める。** 既存の短い作例より長く、入力・分岐・計算・表示を含む
   PC-1245のBASICを1本選ぶ。元ファイルは保ち、検証にはコピーを使う。
   代表入力、期待する表示、修正したい点を先に記録する。
2. **現行機能で解析・修正する。** VS Code Copilotのローカル実行先を使い、
   MCPから構成と処理を調べ、指定箇所の修正を提案する。
   取得上限、必要な範囲を見つけるまでの手順、根拠を示せなかった箇所を記録する。
3. **変更前後を比較する。** Studioで差分を確認して承認し、Build・Load・RUNと
   代表入力でのLCDを照合する。修正した挙動と、変更の影響を受けない既存の挙動を各1件以上確認する。
4. **改善対象を1件に絞る。** 取得量や参照箇所の特定が障害なら、行範囲での取得や検索を候補にする。
   評価で確認した不便を優先し、索引や解析メモ保存の追加は結果を見て決める。

**ここで一区切り。** 題材・入力・期待値・実測値、Copilotで使った操作、詰まった箇所、
次に直す1件を記録する。現行機能で最後まで通らない場合は、該当工程と再現条件を記録し、
通った扱いにはしない。この区切りに公開作業は含めない。

## 公開準備を再開するときの手順

**次の区切りは、検証済み成果物を添付したGitHub Pre-releaseの下書きが、公開可否を判断できる状態になること。**
この手順は、完成度の評価後に公開準備へ戻ると決めた場合に実施する。公開はその内容を確認してから別途判断する。

1. **最新候補を作る。** バージョンは `1.2.0-ai-preview.1`。AI作業ブランチの
   最新の検証対象コミットを指定して、macOS arm64向けの署名・公証済みDMGを作る。
   ファイル名・SHA-256・署名・公証を照合する。
2. **受入れと配布案内を更新する。** PC-1245のBASIC一括入力、PC-1251のCALL再試行と
   機械語の解析、Claude DesktopとVS Code Copilotの接続を同じDMGで確認する。
   Gemini CLIは初回の公開条件から外し、未検証と明記する。登録済みROMの前提、
   MCP設定、通常版を上書きせずに試す手順と復帰手順を案内する。
3. **StableのCIと衝突しない公開経路を確定する。** 現行の通常ワークフローは `v*` タグで起動する。
   Previewタグを作る前に通常リリースを起動しない命名・設定を確認する。
   例：`studio-ai-preview/1.2.0-ai-preview.1` を候補とし、衝突がなければ受入れ済みソースコミットに結び付ける。
   検証結果だけを追記した後続コミットを成果物のソースとして扱わない。
4. **下書きをレビューする。** Pre-releaseフラグ、対象コミット、配布物、ハッシュ、説明、
   StableがLatestのままであることを確認する。ここで止め、下書きURLと公開前の残件を報告する。

初回Previewの公開判断後は、利用時の問題を記録し、再現できるものから次の候補に反映する。
