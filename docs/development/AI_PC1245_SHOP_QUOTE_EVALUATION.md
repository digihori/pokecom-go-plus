# PC-1245 実用BASIC評価：店舗の見積もり

2026-11-12。**実ROMで変更前後の表示を確認済み。Copilotの解析・差分提案と、Studioでの適用・実行を確認済み。**

[評価用プロジェクト](../../test-data/basic/ai/pc1245-shop-quote/README.md)は
PC-1245用の29行・479バイトのBASIC。入力、再入力、2つの分岐、計算用のサブルーチン、
LCD出力を含む。変更要求は小売の加算率だけを5%から10%へ変更すること。
該当箇所はBASIC行番号510の `R=5`。まとめ買いの割引率はBASIC行番号610の `D=10`。

| ケース | 入力（各値の後に ENTER） | 期待値（前 → 後） | 実ROMのLCD（前 → 後） |
| --- | --- | --- | --- |
| 小売の加算率変更 | MODE=1、PRICE=100 | RETAIL 105 → RETAIL 110 | `RETAIL105.` → `RETAIL110.` |
| まとめ買いの回帰確認 | MODE=2、PRICE=100、QTY=2 | PACK 180 → PACK 180 | `PACK180.` → `PACK180.` |

Studioと同じCoreのBASICコンパイラとプログラムイメージのロード経路を使用し、
各ケースを新しい実ROMセッションで起動した。ロード後に RUN と入力キーを送り、
LCDのドット画像を確認した。コンパイル結果は変更前318バイト、変更後319バイト。
比較用の変更は検証コードで一時的に適用し、元のソースは5%のまま残した。
この比較はCopilotによる提案、Studio承認、MCP経由のBuild・Load・RUNの証拠には含めない。

Studioで検証用コピーを開き、プロジェクト名の表示をユーザーと確認した。
前回はフォルダー選択後に画面操作ツールでウインドウを取得できなかったが、今回は
同じ起動中のStudioから画面とMCP応答を取得できた。プロジェクトを開いた時点では未ビルドでLCDは空だった。

VS Code Copilotは `pgp_get_source` で29行を取得し、小売とまとめ買いの分岐および変更対象をBASIC行番号で特定した。
`pgp_propose_source_patch` の差分は510行の `R=5` → `R=10` のみ。Studioで確認して承認し、適用を確認した。
続いてローカルのMCP検証クライアントからBuild・Load・上限付きRUNと入力を提案し、Studioでそれぞれ承認した。
Build成功、319バイトのLoad成功と、変更後のLCDで小売 `RETAIL110.`、まとめ買い `PACK180.` を確認した。
表の変更前の表示は前回の実ROM比較による。今回のStudio経由のLCD確認は変更後の2件。
評価終了後にMCPサーバーを停止した。

モードと価格を1件のキー要求でまとめて送った初回のLCDは `RETAIL0.` だった。
入力欄ごとに要求を分け、次の入力待ち表示を確認してから送ると期待値に一致した。
このケースでは全ソースを一度で取得できたため、長いソースでの取得上限は未評価。

## 一括入力の再現条件

Studioと同じ `DesktopEmulatorRunner` をPC-1245の実ROMで動かした。
小売モードと価格100を一括送信すると、通常のキー間隔（19,200サイクル）では
開始時のCPU状態7通りのうち3通りで、入力欄ごとに送った場合のLCDと一致しなかった。
どの試行でもキー要求の `inputComplete` は `true` だった。
開始時のCPU状態は、ROM起動時の実行サイクルを0、100、1,000、5,000、10,000、20,000、50,000だけ増やして変えた。

続いて、RUNまでは同じRunnerを使い、その後の一括入力はCoreへキーを直接送って間隔を比較した。
ROM起動時に479サイクル刻みで実行時間を変えた105通りを、各モードで比較した。
キーを押す時間は11,520サイクル、通常キーを離してから次を押す間隔は19,200サイクルに固定し、
ENTER後の間隔だけを変えた。表は、入力欄ごとに送ったときとLCDのドットが一致した回数。

| ENTER後の間隔 | 小売（1、100） | まとめ買い（2、100、2） |
| --- | ---: | ---: |
| 19,200サイクル（100 ms） | 42/105 | 0/105 |
| 24,000サイクル（125 ms） | 105/105 | 0/105 |
| 28,800サイクル（150 ms） | 105/105 | 105/105 |
| 38,400サイクル（200 ms） | 105/105 | 105/105 |
| 57,600サイクル（300 ms） | 105/105 | 105/105 |

PC-1245のMCP上限付き実行で、ENTERの後に次のキーがある場合の間隔を28,800サイクルに延ばした。
修正後のStudio実行処理と実ROMを使い、一括入力と入力欄ごとの送信のLCDを比較した。
小売110とまとめ買い180は、それぞれ開始状態105通りすべてで一致した。
修正前の実行処理では、同じ検証でまとめ買いの不一致を再現した。
回帰テストでは、延長した間隔の途中で上限停止すると `inputComplete=false` になり、
後続キーを破棄することを確認した。JDK 21で `build :core:desktopTest` が成功した。
今回の実ROM比較はStudioの実行処理を直接呼び出した。修正版の配布アプリとCopilotの再接続は公開候補の受入れ時に確認する。
