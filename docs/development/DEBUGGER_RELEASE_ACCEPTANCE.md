# Debugger強化：操作性・文書・環境別受入れ

確認日：2026-10-30。`codex/debugger-enhancements`の作業8です。
自動検証・隔離描画・配布runtime生成と、配布アプリ・実ROMの手動受入れを区別します。
作業1〜7の機能実装と今回の自動確認は済んでいますが、全OS・全機種の受入れ完了ではありません。

## 今回の改善

- メモリ側の先頭をMemory Viewにし、検索結果から移動した際に値がすぐ見える配置にしました。
- 位置移動時に入力フォーカスを解放してからスクロールを戻します。
  入力欄への自動スクロールと位置移動が競合せず、エミュレータ入力の所有権も戻ります。
- ROM bank欄の長いラベルを短くし、10進・空欄の意味は説明文に残しました。
- [英語操作ガイド](../guides/DEBUGGER.en.md)を追加し、英語README・目次から案内します。

### 動作確認用パッケージとmacOSの初期確認（2026-10-30）

対象はコミット`9c950f0`です。アプリ表示版は1.0.0、ネイティブパッケージ版は1.6.0です。
[配布パッケージ作成](https://github.com/digihori/pokecom-go-plus/actions/runs/41042116039)で
Windows x64のMSIとLinux amd64のDEBを生成し、取得後のSHA-256照合も成功しました。
macOS署名ジョブは作業ブランチに対するenvironment保護ルールで拒否されたため、実行全体は失敗表示です。
macOS arm64の確認用DMGはローカルで署名・公証なしで生成し、runtimeとディスクイメージの整合性を検証しました。

ユーザーから、このmacOS版の起動・日本語／英語切替・ざっとした基本操作は問題なさそうとの報告を受けました。
これは初期確認の結果であり、以下のU1〜U8全項目の完了を意味しません。
確認先のOS版・表示倍率・機種／RAM構成は未記録です。

### 手動確認で検出した検索パネルの更新不具合

macOSのT05・T06で、Pause後も検索ボタンが無効のまま、入力編集で有効にして検索すると
結果を直ちに古い状態と誤判定する不具合の報告を受けました。
ネストしたComposeセクションがRunnerの通常プロパティだけを読み、ホストのCPU／実行状態の
observableな更新を受け取っていなかったことが原因です。
DebuggerルートでCPU snapshot・実行状態からSession revisionを取得し、検索・RAM編集・ログポイントへ渡すよう修正しました。
日英の画面テストで、入力を書き換えずPause後に検索できること、HEX／16bit LE・BE検索、
Step後の古い結果の拒否と再検索を確認します。配布アプリのT05・T06は修正版での再確認待ちです。

## 配布アプリの手動チェック
