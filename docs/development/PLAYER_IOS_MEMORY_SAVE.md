# iOS Playerのマシン語保存UI整備

2026-11-02。Androidの利用者受入れ後、同じ操作をiOSへ展開。
提出済み0.7.0 build 3の設定と提出内容は変更しない。
開発ソースからの新ビルドは提出済みarchiveとは異なる。

- プログラムメニューをロード／BASICを保存／マシン語を保存へ分割。
- BASICは既存export、マシン語は新しい共有exportAddressSpaceDumpを使用。
  既存のRAM限定exportDump facadeは互換性のため維持。
- メモリ保存は0000〜FFFF、開始≦終了、終了byteを含む。
  ROM・I/O・未割当・ミラーと現在bankの読取り値を保存。LoadのRAM制約は維持。
- 左に開始／終了、中央にCDEF／89AB／4567／0123、右に削除／クリア。
  標準IMEを使わず、4桁目で反対側へ自動切替。4桁の欄への追加は無視。
- 保存・キャンセルはsafeAreaInsetで固定。入力だけ縦横スクロール可能。
- マシン語保存パネルでは機種画面の横向き制限を維持。
  BASIC保存・ロード等の既存パネルの方向方針は維持。
- 入力値はPlayerHostで保持し、画面終了・キャンセルでも保持する。
  新ROM登録・機種起動で新Playerを受け取る際にクリア。アプリ終了には永続化しない。
- 保存は一時ファイルへコピーして標準Files pickerへ渡す。独自の連番は導入しない。

Swift hostテストを追加し、ROM領域0000〜000Fの保存と閉じた後の範囲保持を確認する。
UIテストは両方向の4桁自動切替、標準キーボード非表示、保存可能状態、
閉じて再表示した際の保持、横向き維持を対象とする。
実機の保存先選択・ファイル往復、狭い画面とDynamic Typeの網羅は別途確認する。

## 保存名の表示と保存後の終了

保存予定名を共通の生成処理から取得してBASIC／マシン語の保存画面へ表示。
一時出力ファイルにも同じ名前を使用し、標準Files pickerのタイトルにも設定する。
保存成功は元のパネルもcloseProgramで閉じ、実行前の再開意図を復元。
キャンセル時は従来どおり元のパネルを残し、入力範囲を保持する。
遅延したpickerのonDismissは、成功後に再びパネルを開かない。
関連するSwift host回帰テストと標準Files保存経由のUIテストを更新。

上記変更後、Swift hostの関連4件が成功。標準FilesでDMPを書き出し、
保存画面が消え、再表示時のC500〜C50Fが保持されるUIテストも成功。
結果：iosApp/build/CI-TestResults-20261102-075749.xcresult。
最初のUI実行は背面のアプリ保存ボタンを誤選択して失敗したため、
Filesの保存操作からidentifier=exportProgramを除外して再検証した。
ファイル名表示もUIで確認済み。git diff --check成功。
