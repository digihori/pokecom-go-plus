# SC61860 Assembler

Pokecom GO Studioには、SC61860向けの2パスAssemblerが組み込まれている。

Settings → Assemblerで、内蔵の代わりに外部SC61を選択できる。
設定はStudio全体で共通。[SC61外部アセンブラの利用手順](EXTERNAL_ASSEMBLER.md)を参照。
以下の言語仕様は内蔵Assemblerについての説明。
外部エディタで編集した`.asm`をプロジェクトの`assembly`ソースとしてBuild & Loadできるほか、
Assembly Workspaceでロードせずに結果を確認できる。従来の単発ファイル変換は
`Program` → `Quick Assemble…`として残している。

## Assembly Workspaceの操作

`Project` → `Open Assembly Workspace`から開く。

| 操作 | 結果表示 | ファイル保存 | エミュレータへのロード |
|---|---|---|---|
| Assemble | 更新する | しない | しない |
| Build | 更新する | する | しない |
| Build & Load | 更新する | する | 保存後に行う |

Assembly Workspaceの`Assemble`はMemory、Disassembly、Listing、Symbol Mapをメモリ上で更新する。
結果は画面下部の読み取り専用のAssembly result欄へまとめて表示する。縦・横スクロールバーで
長い結果や行を確認でき、文字の選択・コピーも可能。新しい結果に更新するとスクロール位置は先頭へ戻る。
`Assemble`はファイルを保存しない。`Build`はプロジェクトの`build/`へDMP、Listing、Symbol Mapの3ファイルを生成する。
Assemblyソースが1つの場合はソースの拡張子を除いた名前を使う。例えば`src/pacman.asm`なら
`build/pacman.dmp`、`build/pacman.lst`、`build/pacman.map`となる。Assemblyソースが複数の場合は
結合出力として`program.dmp`、`program.lst`、`program.map`を使う。画面のBuild outputsも同じ保存先を表示する。
出力名変更前の`program.*`など、既存ファイルは自動削除しない。Build outputsの`exists`は
ファイルの存在を示し、最新ソースとの一致やロード済みを保証する表示ではない。
`Build & Load`は保存後にエミュレータへロードする。
ボタン下のEmulator表示で、未ロード・ロード済み・ソース変更後／Buildのみ実行後の旧版ロードを区別する。
ロード成功時は完了表示に対象機種とロードしたバイト数を表示する。保存成功後にロードが失敗した場合も
区別して表示する。ロードはメモリへの配置であり、プログラムの実行はポケコン側のキー操作で開始する。
Workspaceはプロジェクト未選択でも開くことができ、その場合はNew／Open Projectへの入口を表示する。
Sourcesの`Open`は診断の有無にかかわらずソースを外部エディタで開き、Diagnosticsの`Open at line`は
エラー位置を指定して開く。
診断の`Open at line`で行指定に対応する外部エディタを使う場合は、たとえば
`PGP_EDITOR='code --goto {file}:{line}'`をStudio起動時の環境変数に設定する。未設定時はOSの
テキスト編集操作で開くため、行位置までは指定されない。macOSでは`.asm`の関連付け先がStudio自身でも
再投入されないように`open -t`を使用する。

## Quick Assemble

`Program` → `Quick Assemble…`は単一ASMファイルをアセンブルし、指定先へDMPを保存する補助機能。
エミュレータにはロードしない。現在はWorkspaceのような結果プレビューやListing／Mapの保存を備えていない。
結果表示の改善は[Roadmap](../development/planning/ROADMAP.md)に未実装の課題として記録している。

## 基本構文

```asm
ORG 0xC000

START: LII 0x12
       LIDP TABLE
       JRP DONE
TABLE: DB 0x01, &02, 3
DONE:  RTN
```

- コメントは`;`または`#`から行末まで。先頭・途中の独立したコメント行と命令後の行末コメントの両方に対応する。Studioではファイル先頭の連続した`#`行を説明ヘッダとしても表示する。
- ラベルは英字または`_`で始め、英数字と`_`を使用できる。大文字・小文字は区別しない。
- `ORG`で出力開始アドレスを指定する。複数の`ORG`による複数セグメントにも対応する。
- `DB`はカンマ区切りで1バイトの値を配置する。
- 数値は10進数、`0x`、`&`、`$`接頭辞の16進数を使用できる。
- 相対分岐には絶対的な飛び先アドレスまたはラベルを書く。Assemblerが8bit相対値へ変換する。
- `LP`は`LP 0x00`から`LP 0x3F`として、命令コード内に埋め込む値を指定する。
- `CAL`の飛び先はSC61860の命令形式に従い`0x0000..0x1FFF`に限られる。

## 式・定数・データ定義

```asm
BASE EQU 0xC500
SIZE EQU 4

ORG BASE
START: LIA LOW(TABLE)
       LIDP TABLE + 1
       JRP DONE
TABLE: DB "ABC", 0, 'Z', '\xFF'
       DW START, TABLE + SIZE
       DS SIZE, 0xFF
       ALIGN 16
DONE:  RTN
```

`NAME EQU expression`または`NAME: EQU expression`で不変の定数を定義できる。
ORGより前でも定義でき、ラベルと定数は同じ名前空間・大小文字無視の規則を使う。
再定義、未定義名、循環参照はエラー。SETによる再代入は未対応。
命令operand・DB・DW・EQUは前方参照を解決する。定数はSymbol Mapと出力の`.map`ファイルに
`NAME EQU value`として表示し、ラベルのアドレス表示と区別する。

式の優先順位は高い順に以下のとおり。同じ順位の二項演算は左から評価する。

| 優先順位 | 構文 |
|---|---|
| 1 | 括弧、`HIGH(expr)`、`LOW(expr)`、単項`+ - ~` |
| 2 | `* / %` |
| 3 | `+ -` |
| 4 | `<< >>` |
| 5 | `&` |
| 6 | `^` |
| 7 | `\|` |

演算は符号付き32bit整数。各演算のオーバーフロー、ゼロ除算、0〜31以外のシフト数はエラー。
除算はゼロ方向に切り捨て、右シフトは符号を維持する。最終的なbyte/word/命令operandの値域も検査する。
`HIGH`と`LOW`は0〜65535の値の上位／下位byteを返す。
16進数の`0x`、`&`、`$`表記は維持する（例: `DB (FLAGS & 0xFF)`）。

現在位置は`.`で表す。DB/DWで値を複数並べた場合も、その文の開始アドレスを使う。
EQUの`.`は定数の定義行の位置を指し、参照側の位置ではない。
ORG前の`.`は使えない。ORG行にラベルがある場合、そのラベルは従来どおりORG変更前の位置を指す。

ORGの宛先、DSのサイズ、ALIGNの境界は、配置計算の時点で解決できる式に限る。
前方定義の数値EQUや、既に位置が決まったラベルは使えるが、未配置の前方ラベルには依存できない。
反復による配置推測は行わない。EQU依存の深さは最大32、式の構文ノードは最大128、
括弧・単項演算等のネストは最大64とし、過剰な式は診断して停止する。

| 疑似命令 | 出力と制約 |
|---|---|
| `DB expr, "text", ...` | 0〜255のbyteと文字列を連結 |
| `DW expr, ...` | 0〜65535を上位byte→下位byteの順で出力。SC61860のアドレスoperandと同じ順 |
| `DS count[, fill]` | 0〜65536byteを実際に出力。既定fill=0、fillは0〜255 |
| `ALIGN boundary[, fill]` | 次の境界まで実際に埋める。境界は1〜65536の2の累乗、既定fill=0 |

DSは未出力の穴を作らない。DS 0と、既に整列済みのALIGNはbyteを出さずListingにも載らない。
予約・整列の出力もメモリ範囲、ORG重複、ミラー、BASIC衝突の検証対象になる。
出力全体が空の場合は、従来どおりアセンブル失敗になる。

文字列は二重引用符、単一byteの文字定数は単引用符で囲む。
引用符内の`;`、`#`、`,`、`:`はコメント／区切りとして扱わない。
エスケープは`\n \r \t \0 \\ \" \' \xHH`（HHは16進2桁）。
文字はUnicodeコード値0〜255をそのままbyteへ変換し、機種固有の文字コード変換やUTF-8出力は行わない。
日本語等は明示的な機種文字コードをDBで指定する。空文字列は0byte、文字定数はちょうど1byteに限る。

INCLUDE、INCBIN、マクロ、条件アセンブル、ファイル間シンボル共有は未対応。

Disassemblerが生成する`.asm`は、このAssemblerで再び機械語へ変換できる。
アセンブルエラーには元ソースの行番号と理由が表示される。

## 命令とバイト保持

`TEST`には8bitの即値が必要（例: `TEST 0x01`）。相対分岐は飛び先を16bitアドレスで指定し、
`0xFFFF`から`0x0000`への折返しも計算する。ただし出力セグメント自体をアドレス空間の末尾から
先頭へ跨がせることはできない。

逆アセンブルの`.asm`出力は、元のバイトを保持するため、アセンブル不能な未公開opcodeや
同名NOPの別コードを`DB`として出力する。デバッガの命令表示は引き続きニーモニックを使用する。
選択範囲・セグメント末尾の不完全な命令も、範囲外を読まず`DB`として出力する。
これは機械語のバイト保持であり、元のラベルやコード／データ区別の復元ではない。
未公開命令の新しい名称や動作は追加していない。

`DB 1,,2`や末尾カンマなどの空要素はエラーになる。`0xFFFF`への出力直後に
`0x10000`を指すラベルを定義することもできない。ORG領域の重複は該当ORG行を報告する。

## 機種別配置とロード

新規プロジェクトのAssembly／機械語DMPは以下の開始位置を使用する。
両方を選択した場合はDMPをAssemblyの開始位置+`0x40`へ配置し、サンプル同士の衝突を避ける。

| 機種 | Assembly開始位置 |
|---|---|
| PC-1245/1250/1251/1255 | C500 |
| PC-1261/1350 | 6000 |
| PC-1360 | C000 |
| PC-1401 | 4400 |

これらは初期BASIC本文とポインタを避けたサンプル配置であり、予約領域ではない。
BASICが大きくなる場合や開始ポインタを変更する場合は、配置を調整する必要がある。
既存プロジェクトのORGは自動で変更しない。

Workspaceの`Show memory layout`でRAM、ROM、LCD、制御領域、未割当領域を確認できる。
Memoryプレビューにもセグメントの領域種別とミラーの有無を表示する。
LCD・制御領域への意図的な書き込みは許可するが、LCD更新やbank切替等の副作用がある。
PC-1245の書込可能範囲は互換busの広いwrite窓を維持し、物理RAM容量の保証とは扱わない。

AssembleはAssemblyソースの配置と、ソース間の物理ミラー衝突も検証する。
BuildはDMP・バイナリも含め、読取専用／未割当領域、ミラー先の重複、
初期配置を仮定したBASIC本文とポインタ更新の衝突を拒否する。
同じ値であっても同じ物理位置への二重出力は拒否する。
対象機種のROMがロード済みなら、そのSessionの標準／拡張RAMモードで検証し、
未ロード時の1250/1251/1255は拡張モードを仮定する。

Build & Loadは停止中のSessionの現在のBASICポインタとRAMモードで再検証する。
BASIC本文・ポインタ更新・旧本文の消去まで含めて書込予定を作り、機械語との衝突や
不正データを検出してから、一つの検証済みメモリ画像として適用する。
検証に失敗した場合はBASIC・機械語・LCD・bankを変更せず、元のRun／Pause状態を保つ。
BuildはROM未ロードでも使えるため、Build成功だけでは現在のSessionへのLoad成功を保証しない。

ROM領域へのロード、ROMパッチ、bank指定出力は未対応。PC-1360の`4000..7FFF`は
bank 0〜7のROM窓で、通常のRAM配置先ではない。

## 検証範囲

合成データによる全256opcodeの逆アセンブル往復、独立したPGP命令期待表、operand境界、
全機種の新規テンプレートBuild／Load、RAMモード、ミラー、BASIC衝突、失敗時非変更をテストする。
式の優先順位、符号・値域、定数循環と共有依存、前方参照、文字列とエスケープ、
wordのbyte順、予約・整列と配置検証、Listing／Map出力も合成ソースで検証する。
実機の未公開命令の挙動を確定したという意味ではない。

調査時点（main / 2890cd5）の問題点と実装順序は[アセンブラ調査記録](../development/ASSEMBLER_AUDIT.md)を参照。
