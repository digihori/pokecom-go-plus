# PC-1401実機でのLDPC／MVMP比較

PC-1360Kの[実機比較](../pc1360k/PC-1360K_HISTORY.md)では、両命令の読出し値が
DPと漢字ROM選択値に依存した。PC-1401でもデータ取得がDPに依存するかを、次の命令の
先頭バイトとDPを独立に変えて調べる。PC-1401実機では、全項目が命令直後のバイトを読む場合の予測と一致した。

## 実行

1. PC-1401の必要なBASICプログラムやメモリ内容を退避する。
   試験は短い専用BASICだけをロードした状態で行い、`0x4400〜0x4482` と
   `0x4490〜0x4499` が常駐コード等に使われていないことを確認する。
2. [BASICローダー](ldpc-mvmp-probe.bas)を入力するか、S1 BASICのWAVとして転送する。
   リポジトリ直下からの生成例：

   ```sh
   perl tools/pcwav/pcwav-encode.pl s1basic docs/analysis/pc1401/ldpc-mvmp-probe.bas probe.wav RDPROBE
   ```

3. RUNモードで `RUN`。ローダーが131バイトをPOKEし、`CALL 17408` で
   `0x4400` のプローブを呼ぶ。正常時は結果を表示せずBASICへ戻る。
4. 下記の各番地を通常のBASICのPEEKで読み、機種名と値を記録する。
   例：`PRINT PEEK(17554)`。A/Bは同じ命令の別の実行位置を指す。

| 項目 | 結果番地（10進） | 命令直後のバイトを読む場合（10進） | 通常RAMのDP先を読む場合（10進） |
| --- | --- | --- | --- |
| RAM確認値 | 17552, 17553 | 165, 90 | 165, 90 |
| LDPC A | 17554, 17555 | 3, 3 | 165, 90 |
| LDPC B | 17556, 17557 | 18, 18 | 165, 90 |
| MVMP A | 17558, 17559 | 89, 89 | 165, 90 |
| MVMP B | 17560, 17561 | 18, 18 | 165, 90 |

各組は DP=`0x4490`、`0x4491` の順。RAM確認値が違えば、まずロード・実行条件を確認する。
両予測と異なる場合も、そのまま記録する。後続バイトと同じ値が得られても、外部バスに
DPが一切現れないことまでは示さない。DP依存が見えても、その結果だけで1360KのA16/A17の
配線やゲートアレイの動作を確定できない。

[アセンブリ](ldpc-mvmp-probe.asm)はI/O出力・バンク選択レジスタへの書込みを行わず、
A/B/Pと内部RAM `0x20` を復元する。DP・演算フラグは保存しない。

PGPでは、ローカルのPC-1401 ROMでBASICをロードし、RUNによるDATA→POKE、CALL、RTN後の
結果を確認した。131バイトのロード内容はアセンブル結果と一致し、結果は
`165,90 / 3,3 / 18,18 / 89,89 / 18,18`。これはエミュレータの比較基準であり、
PC-1401実機の測定結果ではない。

## PC-1401実機の結果（2026-11-11）

実機で全項目が「命令直後のバイトを読む場合」の列と一致したとの報告を得た。
表の順では、RAM確認値が `165,90`、LDPC A/B が `3,3 / 18,18`、
MVMP A/B が `89,89 / 18,18` に対応する。

この試験条件では、DPを変えても結果は変わらず、後続命令の先頭バイトを変えると
結果が変わった。PC-1401の結果はPGPの通常経路と一致し、PC-1360Kの漢字ROMアクセス
で確認したDP依存とは異なる。PC-1251実機での動作、PC-1401の外部バス上のDP信号の
有無、PC-1360KのCPUとゲートアレイの役割分担までは、この比較からは決められない。
