# PC-1360K READの上位アドレス比較

> この文書は個別実験の経過記録です。「未取得」「未実装」等は各記述時点の状態を示します。
> 現在のまとめは[PC-1360K 漢字ROM解析とStudio対応](../../machines/PC-1360K.md)、
> 吸い出し用BASICの使い方は[配布用手順書](../../../tools/pc1360k-rom-dump/README.md)を参照してください。

2026-10-18。実機での結果を受領。

## 実行方法

[read-address-range.bas](read-address-range.bas) を新しいBASICプログラムとして
実機に入力し、RUNする。PRINTごとに停止するため、結果を控えてENTERで進める。
4行分の表示後もENTERを押して終了する。WIDTHや漢字キーの事前操作は不要。
以前の確認と同じ実機・初期状態で実行し、事前操作が異なる場合は併記する。

| 表示 | 0x3600への書込み値 | READに渡すDP（左から順） |
| --- | --- | --- |
| 0T | 0 | 0157, 4157, 8157, C157 |
| 0G | 0 | 237D, 637D, A37D, E37D |
| 1T | 1 | 0157, 4157, 8157, C157 |
| 1G | 1 | 237D, 637D, A37D, E37D |

Tは既に読めた一覧表の一部、Gは「あ」の字形の一部を基準にしている。
過去の実測ではselector 0の0157は35、237Dは241だった。
今回も同じ条件で読めるかを最初の値で照合できるが、値を強制・補正しない。

返却用の書式（すべて10進数）：

```text
0T: ?,?,?,?
0G: ?,?,?,?
1T: ?,?,?,?
1G: ?,?,?,?
```

## 何が分かるか

各行では下位14ビットを固定し、上位2ビットだけを変えている。
値が異なれば、その組合せの上位ビットが読み出し結果に影響すると判断できる。
同じ値でも、偶然同じデータが置かれている可能性があるため、アドレスの折り返しや
容量の確定には追加の連続データ比較が必要。

これはアドレス範囲を調べる最初のサンプル比較であり、全領域の境界確認や
256KiBの構成を確定する試験ではない。通常ROMバンクからの独立性、Fポートによる
選択、物理的なS/Tチップの対応も、この試験単独では確定しない。

## プログラムと検証

機械語はC000..C0BAの187バイト、出力はC200..C20F。
BASICがCALL後にC210へ165、全PRINT後にC211へ90を書き込む。
C000..C211を使用可能なRAMとして確保すること。以前のプローブと同様、
この領域の既存データは上書きする。

全16回のREADは同じ機械語位置C0B7（命令56）を使用する。
その直後の命令も常にLIB 6Dで、命令位置による違いを除いて比較する。
A/B/Pとスタックを保存・復元し、0x3600は最後に1となる。
Fポート出力命令と通常ROMのバンク切替レジスタ3400への書込みは含めていない。

現行StudioのREADは次のPCのバイトを読むため、比較値はすべて3となる。
これは実機の期待値ではなく、現行エミュレータでの検証用基準値。
合成ROMでのレジスタ保存・スタック復元と、ローカルの標準ROMを用いた
BASICのDATA/POKE、CALL/RTN、4回のPRINT継続、終了マーカーを確認した。

再現用：JDK 21を指定し、次を実行する。

```sh
PGP_ANALYZE_PC1360K=1 PGP_PC1360K_RANGE=1 ./gradlew --gradle-user-home .gradle-local build
```

解析用ROM・トレース・生成バイナリはlocal-data以下にのみ保存し、共有対象にしない。

## 実機結果（2026-10-18）

| 表示 | 第1値 | 第2値 | 第3値 | 第4値 |
| --- | ---: | ---: | ---: | ---: |
| 0T | 35 | 128 | 245 | 16 |
| 0G | 241 | 67 | 240 | 15 |
| 1T | 14 | 240 | 68 | 177 |
| 1G | 65 | 22 | 88 | 86 |

selector 0の0157=35、237D=241は、それぞれ以前の一覧表・字形読み出しと一致。
各行の4値が異なるため、測定した2つの下位アドレスでは、上位2ビットの
4通りが区別される。今回の条件で単純に下位14ビットだけへ折り返すモデルとは
一致しない。上位ビットが通常のROMアドレス線として機能するか、別の選択に
使われるかの物理的な区別までは、この結果だけではできない。

また、8つのDPすべてでselector 0と1の値が異なる。
現状の作業仮説は「16ビットDPと3600の選択値でアクセス先を指定できる」。
これは2×64KiBの論理的な指定方法に相当するが、128KiBの全位置が独立した
ROMデータであること、全容量、S/Tとの対応を確認したものではない。

次はこの読み方で連続ブロックを取得し、再読一致とアドレス境界を確認する。
その後、DP 0000..FFFFをselector 0/1それぞれで回収する方法を整える。
残りの領域やFポートの関与は、回収データと配線の照合を基に調べる。
