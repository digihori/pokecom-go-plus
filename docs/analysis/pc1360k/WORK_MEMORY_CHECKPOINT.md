# PC-1360K ワークメモリ解析：中断・再開メモ

2026-10-31、ユーザーの希望で一旦中断。

## 現在の停止状態

- 機種：PC-1360K、WIDTH 2。最後の入力は「かんじ」の変換。
- 通常ROM bank 6、次PC `0x4494`。`CALL 0x4AA8` から戻った直後、`CALL 0x44DC` の前。
- 8バイト結果表：`0x2053` から29件、終端 `0x213B`、管理値 `0x2372〜0x2373=0x213C`。
- 5バイト別表：`0x2381` から18件、終端 `0x23DB`、管理値 `0xFBDC〜0xFBDD=0x23DC`。
- Breakpoint id 1：bank 6 `0x4494`、有効。
- Breakpoint id 2：bank 1 `0x543D`、無効。
- Watch id 0：`0x2381〜0x2572` のwrite、無効。
- Trace：4096件、有効。待機まで走らせると解析区間が上書きされる。

この状態でエミュレータを停止したままにしている。
再開時はMCPで現在位置・セッションrevision・登録状態を再取得し、上記と一致するか確認する。
認証情報やsession IDは公開文書へ記載しない。

## ここまでに確認したこと

[読み物の本文](../../reference/machines/PC-1360K_KANJI_RUNTIME.md)に安定した説明を、
[観測記録](KANJI_WORK_MEMORY.md)に条件・Traceの根拠・仮説の修正を残している。

- 保存済みの混在文字列は、今回のLIST・PRINTとも追加RAM全域read/write Watchで停止しなかった。
- LISTは保存CP932からJISへ変換し、共通字形取得へ渡す。
- 「幹」「事」は圧縮側の字形取得・展開を通り、CPU内部RAMと `0xFEB0` のバッファを使った。
- 入力変換ではROM内位置・項目位置、8バイトの結果表、5バイトの別表を追加RAMに置く。
- 別表は元の結果番号を保持し、絞込み・属性変換・読み消費量の延長を含む。
- 「感じ／候補6」→「幹事／候補5」と選択位置0→1を対応付けた。
- 「亜」「幹事」の採用後も追加RAMの前後内容は同じ。残存と有効性は区別が必要。

生コンテキストは無視対象の `local-data/analysis/pc-1360k/work-memory/`。
最新は `68-secondary-table-completed-pause.json`。ROM・字形・辞書の大量出力をGitへ追加しない。

## 次に追う課題

1. 完成した5バイト表の+4が `0xFF` から `0xA9` 等へ変わる条件と更新元。
2. 消費量を増やすROM表の照合規則。元表番号12で1→2、番号18で2→3を実測済み。
3. 5バイト表から `0x2573` 周辺の選択状態を作る過程。元表・別表・文節の対応。
4. `0x2040〜0x2049` と画面の候補表示数の生成元、複数の選択成分の関係。
5. 起動時初期化、CLEAR、採用時の有効状態の切替。前後比較だけでなく短区間で捕まえる。

同じ既知ループの全書込みで止め続けず、対象フィールド・生成元にWatchやBreakpointを絞る。
新しいデバッグ設定はMCPの提案を作り、Studio UIの承認後に登録成功を確認する。

## セッションを閉じた場合

実ROMセットでPC-1360Kを起動し、必要なRAM初期化を済ませ、WIDTH,2へ設定する。
漢字モードでKANJIを入力し「かんじ」を確認して変換する。
bank 6 `0x4494` のBreakpointと、調べる領域のWatchを事前に準備する。
現在のBASICプログラムは[表示試験用ソース](samples/kanji-display.bas)であり、
変換実験のためにRUNする必要はない。
