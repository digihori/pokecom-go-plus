# PC-1360K 境界をまたぐ連続読み出し・再読確認

> この文書は個別実験の経過記録です。「未取得」「未実装」等は各記述時点の状態を示します。
> 現在のまとめは[PC-1360K 漢字ROM解析とStudio対応](../../reference/machines/PC-1360K.md)、
> 吸い出し用BASICの使い方は[配布用手順書](../../../tools/pc1360k-rom-dump/README.md)を参照してください。

2026-10-18。実機結果を受領。

[read-boundary-repeat.bas](read-boundary-repeat.bas) を新しいBASICプログラムとして
実機でRUNする。PRINTで停止するごとに値を控え、ENTERで進める。
最後のDの表示後にもENTERを押す。WIDTHや漢字キーの事前操作は不要。
前回と同じ初期状態で実行し、異なる事前操作があれば併記する。

| 表示 | 3600への書込み値 | DP（左から順） |
| --- | --- | --- |
| 0L | 0 | 3FFC, 3FFD, 3FFE, 3FFF |
| 0H | 0 | 4000, 4001, 4002, 4003 |
| 1L | 1 | 3FFC, 3FFD, 3FFE, 3FFF |
| 1H | 1 | 4000, 4001, 4002, 4003 |
| D | — | 1回目と2回目の16バイトのうち、不一致だったバイト数 |

D=0なら再読は全一致。0以外でも、出た数をそのまま記録する。

```text
0L: ?,?,?,?
0H: ?,?,?,?
1L: ?,?,?,?
1H: ?,?,?,?
D: ?
```

## 目的と判断できる範囲

上位アドレスの比較では、同じ下位14ビットに対して異なる値が得られた。
次は3FFF/4000の境界付近で隣り合う値を取得し、再読の安定性を確認する。
取得データは今後の連続吸い出しと照合する実測資料になる。
ただし、8バイトだけでは全領域の境界特性・容量は確定できず、境界の前後で
数値が似ているかどうかだけで物理配線やアドレスの連続性を断定しない。

## 使用領域

機械語はC000..C166の359バイト。READ命令は全32回ともC163の同じ位置を使用する。
DPは各回LIDPで明示設定する。自動インクリメントの動作確認ではない。
1回目はselector 0の8バイト、selector 1の8バイトの順でC200..C20Fに保存。
2回目も同じ順で読み、C210..C21Fに保存する。
BASICで比較後、4行の1回目データとDを表示する。

C220はCALL復帰マーカー165、C221は全表示終了マーカー90、C222は不一致数。
C000..C222を使用可能なRAMとして確保すること。この領域の既存データを上書きする。
A/B/Pとスタックを保存・復元し、3600は最終的に1にする。
機械語にはFポート出力命令と3400への書込みは含めない。

## 検証

合成ROMで32回のDPとselectorの順序、保存レジスタ・スタック復元を確認。
ローカル標準ROMでBASICのDATA/POKE、CALL/RTN、5回のPRINT継続、
D=0と終了マーカーまでを確認した。現行StudioのREADは次のPCを読むため、
データはすべて3になる。実機の値を予測したものではない。

JDK 21での再現用：

```sh
PGP_ANALYZE_PC1360K=1 PGP_PC1360K_BOUNDARY=1 ./gradlew --gradle-user-home .gradle-local build
```

実測値・生成バイナリはlocal-data以下で管理する。

## 実機結果（2026-10-18）

```text
0L: 0,0,0,0
0H: 128,128,128,128
1L: 0,0,0,0
1H: 191,2,253,134
D: 0
```

両selectorの3FFC..3FFFは00 00 00 00。
4000..4003はselector 0で80 80 80 80、selector 1でBF 02 FD 86。
D=0より、selectorを0→1→0→1と切り替えた今回の2回分の16バイトは全一致。
この範囲では、切替後に同じDPを再読する手順の再現性が確認できた。

境界の前後で異なる値が得られたが、それだけでハードウェアのバンク境界とは
判断しない。3FFC..3FFFが両selectorでゼロである理由も未確定。
データ中のゼロか、未実装領域等かは、周辺の連続データとの照合が必要。
全範囲の安定性、全容量、Fポート条件、S/Tチップとの対応は引き続き未確定。

次は小規模な点の手入力確認から、ブロック単位の回収と照合に移る準備をする。
既知の一覧表・字形・今回の境界データを回収結果の照合点として利用できる。
