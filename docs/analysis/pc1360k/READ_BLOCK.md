# PC-1360K 256バイトのブロック回収

> この文書は個別実験の経過記録です。「未取得」「未実装」等は各記述時点の状態を示します。
> 現在のまとめは[PC-1360K 漢字ROM解析とStudio対応](../../reference/machines/PC-1360K.md)、
> 吸い出し用BASICの使い方は[配布用手順書](../../../tools/pc1360k-rom-dump/README.md)を参照してください。

2026-10-18。初回256バイトの実機回収・ファイル照合を確認。

## 最初の回収手順

1. [read-block.bas](read-block.bas) を新しいBASICプログラムとして実機へ転送する。
2. RUNする。初期設定はselector 0、DP 0100..01FF、256バイト。
3. SUM（1回目の256バイトの単純合計）とD（再読で不一致だったバイト数）を控える。
   各PRINTで停止するのでENTERで進め、Dの後もENTERを押して終了する。
4. D=0であることを確認し、次のコマンドでRAMの256バイトを音声出力・録音する。

```basic
CSAVE M 53248,53503
```

これはD000..D0FFの保存。CSAVE Mは指定した開始〜終了アドレスをバイナリ形式で
保存する命令（Sharp PC-1360 Operation Manual、印刷ページ141）。
[取扱説明書](https://minuszerodegrees.net/manuals/Sharp/Sharp%20PC-1360%20-%20Operation%20manual.pdf)

5. 既存のpcwavで録音をS1 Binaryとしてデコードし、ヘッダー等を除いた
   **256バイトのペイロード**を取り出す。WAV原本も保持する。
6. SUM、D、録音WAVまたはデコード済みバイナリを解析用に渡す。

最初のファイル名の例は`read-s0-0100-01ff.bin`。
録音・デコードの成否は実機で確認する必要がある。StudioのS1 WAV対応は
今回追加していない。pcwav参照元は同一作者の既存ツールで、変更していない。

## ファイル受領後の照合

- サイズが256バイトであること。
- 全バイトの合計が実機のSUMと一致すること（合計だけで完全性は保証しない）。
- ファイルのオフセット0056..005Bが、以前実測したDP 0156..015Bの
  `00 23 5A 00 1D 1D`と一致すること。

確認後、取得範囲を広げる。先に全領域を独立したROMと断定しない。

## プログラムの構成

機械語C000..C020（33バイト）、1バイト出力C200。
BASICがC006のselector即値とC00C/C00DのDP即値を書き換え、CALLごとに
1バイト読む。READ命令は常にC00E。各CALLでA/B/Pとスタックを保存・復元する。
3600は各CALLの最後に1となる。Fポート出力・3400への書込みは含めない。

1回目の256バイトをD000..D0FFに保存し、2回目は各バイトをその場で比較する。
2回目の値でバッファを上書きしない。従ってDが0でない場合も1回目の内容が残る。
結果用にC210..C215を使用する。C210は取得完了165、C211は表示終了90、
C212/C215は不一致数の上位/下位、C213/C214は合計の上位/下位。
これらの領域と機械語・出力バッファの既存データは上書きする。
実機側で該当RAM領域が利用可能であることを確認する。

行60のS、A、Nは選択値、読出し開始アドレス、長さを表す。
初回は変更せず使用する。後続の256バイト回収ではS=0/1、0<=A<=65280、
N=256の範囲で開始アドレスを変更できる。出力先は常にD000。
今回の検証は初期設定で行っており、全範囲は実機で未確認。

## 検証済み範囲

合成ROMで命令位置、パッチ用オペランド位置、保存レジスタ・スタックを確認。
ローカル標準ROMでBASICから512回のCALL、256バイト保存、合計、再読比較、
2行の表示と正常終了を検証した。

現行StudioのREADでは全バイトが3、SUM=768、D=0となるが、これは実機の期待値ではない。
検証時だけREAD直後のAへDP由来の可変パターンを入れる試験ではSUM=32640となり、
2回目の1バイトを変更するとD=1となることも確認した。
CPUや実機のメモリマッピングには、このパターンを実装していない。

JDK 21での再現用：

```sh
PGP_ANALYZE_PC1360K=1 PGP_PC1360K_BLOCK=1 ./gradlew --gradle-user-home .gradle-local build
PGP_ANALYZE_PC1360K=1 PGP_PC1360K_BLOCK=1 PGP_PC1360K_BLOCK_FAULT=1 ./gradlew --gradle-user-home .gradle-local build
```

実機のROM由来データ・生成バイナリ・録音はlocal-data以下で管理する。

## 初回ブロックの実機結果（2026-10-18）

ユーザー提供のblock.binは256バイト。実機SUM=7380、D=0。
ファイルの合計も7380で一致し、オフセット0056..005Bの6バイトは以前の
一覧表読出しと完全一致した。今回の取得・再読比較・ファイル転送の結果は
既知データと整合する。ファイルはlocal-data以下へ保存し、共有対象には含めない。

SHA-256: `f55fee8e7215cf688e214ff3933e62e8a25e28f7c55b4d014de3eab9194670ec`

### 次の照合ブロック

同じプログラムの行60だけを変更する。

```basic
60 S=0:A=8960:N=256
```

DP 2300..23FFを読み、D000..D0FFへ保存する。RUN後のSUMとDを控え、
最後までENTERで進めてから、前と同じ保存コマンドで録音する。

```basic
CSAVE M 53248,53503
```

ファイル名の例は`read-s0-2300-23ff.bin`。
既に読めた「あ」の30バイト（2378..2395）が、このファイルの
オフセット0078..0095に一致するかを確認する。実機結果は未取得。
新しいデータ取得で出力バッファが上書きされるため、前の回収ファイルは保持する。

## 第2ブロックの実機結果（2026-10-18）

selector 0、DP 2300..23FFのblock1.binを受領。256バイト、
実機SUM=8079、D=0。ファイル合計も8079で一致。
オフセット0078..0095は、以前取得した「あ」の30バイトと完全一致した。
既存の字形データの転記（行4の二重カンマを余分な区切りと解釈した箇所を含む）も
今回のファイルと整合する。2つの離れた範囲で既知データとの一致を確認できた。

SHA-256: `08ef0633fa9bd37209f83e677a4f533dad55377185e128c49945b340f496989f`

selector 1のファイル回収はまだ未確認。次に同じプログラムの行60を
`60 S=1:A=256:N=256`として0100..01FFを回収すれば、
オフセット0057が過去のselector 1の0157=14と一致するかを確認できる。
SUM・Dと256バイトのファイルを照合する。保存先とCSAVE Mコマンドは同じ。

## 第3ブロック：selector 1の実機結果（2026-10-18）

selector 1、DP 0100..01FFのblock2.binを受領。256バイト、
実機SUM=30624、D=0。ファイル合計も30624で一致。
オフセット0057は14で、以前のselector 1、DP 0157の値と一致した。
同じ範囲のselector 0のファイルとは256バイト中256バイトが異なる。
selector 1でも、限定範囲の再読・ファイル転送・既知値との一致を確認できた。
全領域の独立性、物理チップ対応や全容量は依然未確定。

SHA-256: `7f053af4a74475801f29c5ef3a70d743bc6d465dd1bcdb20520c07061c8de5ec`

これで小規模確認は一区切りとし、次はブロック回収の効率化を準備する。
現行版は1バイトごとにBASICからCALLするため、全域回収には時間がかかる。
拡大する場合は、合計値・不一致数の保存幅、使用RAM領域、境界条件も
合わせて検証する。未検証のまま行60のNだけを増やさない。
